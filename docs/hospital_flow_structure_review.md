# 수학 모델 적용 후 구조·데이터 점검

## 수정한 구조

| 문제 | 변경 | 효과 |
|---|---|---|
| 결과 대기 전체를 장비 점유로 처리 | `hospital_test_model.test_timing()`에서 점유시간과 결과 turnaround 분리. `test_resource_release`와 `test_result_ready` 이벤트 분리 | 장비가 먼저 비워지면 다음 환자가 사용 가능. 결과 지연이 장비 이용률에 중복 반영되지 않음 |
| 이전 환자 결과 도착 시 이미 재배정된 장비를 해제할 위험 | 새 결과 이벤트는 pending test와 일치 여부를 확인하고 장비 소유권을 변경하지 않음 | 다른 환자의 예약을 보존 |
| 스케줄러·정체 분석·뷰어의 검사 자원 분류 중복 | `hospital_test_model.test_resource_type()`을 공동 사용 | 초음파 분류 차이 제거, Lactate의 `ct` 부분 문자열을 CT로 오인하는 오류 수정 |
| 검사명만으로 자원 추론 | `resource_profile.test_resources` 명시 매핑 우선 | 기관별 검사명이나 약어를 명확히 지정 가능. 없는 매핑은 추론 사실 표시 |
| 잘못된 서비스시간이 실행 도중 발견 | 초기화 시 검사별 시간·자원 스키마 검증 | 음수·NaN·지원하지 않는 자원·점유>turnaround는 실행 전에 오류 |
| 대체값 사용 여부가 결과에서 불명확 | `executed_test_assumptions` 및 data_gaps 출력 | 명시 데이터·설정 기본값·turnaround 대체·이름 추론을 구분 |
| 분기·재개에서 분리 이벤트 유실 가능 | await 분기는 반환/결과 이벤트 모두 보존, diagnose는 둘 다 취소, 기존 결합형 이벤트도 지원 | 새 구조의 what-if 및 구형 스냅샷 호환성 유지 |

적용 범위는 병렬 엔진이다. 기존 단일 환자 엔진의 시간 모델은 별도다.

## 새 데이터 계약

아래 숫자는 코드 사용 예시이며 실측값·임상 권장값이 아니다.

```json
{
  "resource_profile": {
    "test_resources": {"Chest CT": "imaging_slot"},
    "test_occupancy": {"Chest CT": 5},
    "test_turnaround": {"Chest CT": 20}
  }
}
```

검사 시작을 t라고 하면 장비 반환은 t+5, 결과 공개는 t+20이다. 둘 다 분 단위이며 양수, 점유≤turnaround가 필요하다. turnaround는 검사 시작부터 결과 공개까지로, 검사 전 큐 대기는 포함하지 않는다. 점유시간에 준비·청소가 포함되는지는 데이터 제공자가 일관되게 정의해야 한다. 현재는 결과보다 늦게 끝나는 청소/점유를 지원하지 않으며 그런 입력을 거부한다.

지원 자원은 `lab_slot`, `imaging_slot`이다. CT/MRI 전용 pool을 구현한 것은 아니다. 검사명 키는 정확히 일치해야 한다. 알려진 modality 단어만 보조 분류에 쓰며, 비표준 약어·한국어 검사명 등에는 명시 매핑을 권장한다.

점유시간 누락 시 turnaround를 점유시간으로 쓰는 기존 동작을 유지한다. 결과시간도 누락되면 설정 기본값을 쓴다. 현재 5명 예제는 점유시간이 없어 `missing_test_occupancy`, 명시 자원 매핑이 없어 `inferred_test_resource`를 보고한다. 데이터 부족 목록은 실행된 검사에 대한 기록이며 모든 잠재적 검사에 대한 완전한 데이터 감사는 아니다.

## 아직 필요한 데이터와 구조

| 우선순위 | 필요한 것 | 이유 / 남은 작업 |
|---|---|---|
| 1 | 검사 시작·장비 반환·결과 공개 시각, 명시 자원 종류 | 방금 분리한 모델에 실측값 입력. 필수 키: case_id, test_name, resource_id, start, release, result_ready |
| 1 | 도착·각 큐 진입/이탈·진료 시작/종료·퇴실 시각 | λ, 서비스시간 분포, 최초 진료 대기, 체류시간 교정. 재방문은 visit_id로 구분할 필요 |
| 1 | 독립 critical_patient 라벨과 라벨링 기준 | WTE의 독립 평가. 스케줄러가 산출한 ESI를 정답처럼 재사용하지 않음 |
| 1 | 환자별 악화 임계값과 기준 시계, 전문가 검토 | 현재 threshold 모델의 임상적 타당성. 없으면 악화 전이를 생성하지 않음 |
| 2 | CT/MRI/초음파별 자원 목록·수량·시간, 직원 근무표 | 장비별 pool과 시간 가변 용량, 교대 모델 설계에 필요 |
| 2 | 처치마다 필요한 의사·간호사·장비와 동시 점유 규칙 | 복수 자원 원자적 획득/해제 및 교착 방지 정책 필요. 일반 간호 부하도 현재 미구현 |
| 2 | 진단 확정→입원/퇴실→침상 청소 완료 시간 | 현재는 진단 확정 시 침상을 반환하므로 실제 병상 회전율과 차이. 별도 병상 해제 전이 필요 |
| 2 | 처치 시각·효과·회복/악화 관측 | 회복 및 처치 반응 모델 정의에 필요. 임의의 치료 효과를 넣지 않음 |
| 평가 전 필수 | 관측 데이터와 정답 데이터의 정책 경계 분리 | 기존 demo 정책은 gold_label을 참조하고 일부 검사 수치도 합성함. 흐름 시연에는 사용 가능하나 독립 진단 정확도 평가에는 사용 불가. 독립 임상 정책·검사결과 계약이 필요 |
| 실험 전 필수 | 반복 seed, warm-up/관측 구간, 기준 정책, 효과 지표 | 한 번의 완료 결과로 실제 수요의 안정성·최적성 결론을 내릴 수 없음 |

장비 pool 분리와 복수 자원 모델은 실제 자원 목록·업무 요구를 받아 다음 구조 확장으로 진행해야 한다. 지금 CT 수량, 간호 부하, 회복률을 임의로 생성하지 않았다.

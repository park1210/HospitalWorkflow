# 4장 확장 방향을 제외한 보완 사항

## 문서 장별 적용 범위

| 장 | 부족했던 부분 | 반영 내용 / 남은 제한 |
|---|---|---|
| 1 연구 개요 | 과정 평가가 반복 실행과 분리 | 동일 엔진의 상태·이벤트·5장 평가·6장 지표를 실행별 JSON에 저장 |
| 2 현재 한계 | 최종 정확도만으로 비교할 위험, 데이터 부족 불명확 | readiness.json에 누락 annotation·지원하지 않는 실험·연구 주장 제한을 기록 |
| 3 기존 연구 흐름 | 정적 QA·대화형·동적 환경의 결과가 혼동될 가능성 | 현재 실행을 deterministic parallel demo로 명시. 정적 QA/LLM 결과로 대체하지 않음 |
| 5 평가 | 개별 실행 간 비교만 존재 | 자원 비교에 동일 환자·동일 도착·동일 annotation 대응 비교 적용. 그룹별 지표 및 누락 수 보존 |
| 6 수학 모델 | 4개 물리 침상이 계산 실험의 한계 | headless cohort_unconstrained 기준선 제공. 물리 뷰어에서는 표시를 거부 |
| 7 실험 설계 | 환자 수/도착 부하/자원 조건의 재현 가능한 조합 실행 부재 | JSON 계획 기반 실행기, 반복 seed, 조건별 요약, 원본 실행 기록, 해시와 코드 provenance |
| 8 예상 기여 | 구현과 입증된 연구 결과 구분 부족 | demo 흐름 실험과 독립 임상 성능을 분리. 결과 파일에 허용되지 않는 연구 주장 명시 |
| 9 참고문헌 | 원문 지표와 연구 자체 정의 혼동 가능 | hospital_metric_provenance.json에 참고식/응용/자체 정의 구분. 서지·DOI는 원문 전사이며 독립 검증하지 않았음을 명시 |

4장의 라우팅·불확실성·Governor·Fault Injector·장기 기억 등 새 연구 방향은 추가하지 않았다.

## 실행

```powershell
python -m app.scripts.run_hospital_experiments --scenario-file data/raw/er_multi_patient_simulation_scenario.json --output-dir outputs/reports/my_chapter7_experiment
```

출력 폴더는 새 경로여야 한다. 기존 결과를 덮어쓰지 않는다. `--plan`으로 계획을 바꾸고, `--annotations`로 case_id별 evaluation 객체를 제공할 수 있다. annotation은 모든 조건 실행 전에 한 번 고정된다. 명시한 scenario 파일을 사용하며 USE_PROCESSED_CASES 환경 설정으로 다른 입력을 대신 읽지 않는다. 추가 LLM 호출이나 모델 다운로드는 없다.

예제 계획: `app/data/hospital_experiment_plan.example.json`.

- 환자 수: 1, 3, 5, 10.
- seed: 11, 23, 47. seed별로 원본 환자 순서를 섞고 환자 수별 prefix를 사용한다. 동일 seed에서 작은 코호트는 큰 코호트의 부분집합이다.
- 도착: Poisson 0.2명/분과 1명/분. **설명용 가상 부하이며 실측 정상/혼잡 기준이 아니다.**
- 자원: 기본 제약 / cohort_unconstrained.
- 관측 상한: 240분. 조기 완료하면 중단한다. 미완료 환자를 실패 진단 또는 대기 0으로 변환하지 않는다.

입력 환자가 부족하면 해당 환자 수와 seed 조합을 건너뛴다. 복제 환자를 만들어 10명 실험을 수행했다고 기록하지 않는다. 현재 5명 시나리오에서는 36개 실행(3개 환자 수 × 3 seed × 2 도착 × 2 자원)과 3개 생략 코호트 조건이 발생한다. 생략된 10명 코호트 조건 3개는 각각 4개 세부 실행에 해당한다.

## 무제약 기준선의 의미

주어진 코호트 크기가 N이면 triage nurse/ER doctor/bed/lab/imaging을 각각 N개, 기존에 등록된 각 전문과의 specialist를 N명 제공한다. 환자 한 명이 같은 종류의 자원을 중복 보유하지 않는 현재 모델에서 환자 간 자원 경쟁을 제거하기 위한 충분한 수량이다.

실제 무한 자원이나 무한 도착의 안정성을 의미하지 않는다. 등록되지 않은 전문과를 새로 만들지 않는다. 개별 진료·검사시간, 이동시간, 침상 배정 후 1분의 기존 준비 지연은 남으므로 최초 진료 대기가 0이 되는 것은 아니다. 논리 자원은 기존 장면 위치를 공유하며 거리 기반 물리 실험에 사용하면 안 된다. 뷰어와 live 실행에서는 이 모드를 거부한다.

자원 조건은 capacities와 resource_mode만 바꿀 수 있다. 서비스시간·우선순위·도착 설정을 자원 조건에 몰래 섞으면 오류 처리하여 비교 교란을 줄인다. 자원 조건별로 같은 환자와 같은 도착 난수 seed를 사용한다. 다른 환자 수 사이의 비교는 코호트 구성도 달라지므로 환자 수만의 인과효과라고 해석할 수 없다.

## 산출물

| 파일 | 내용 |
|---|---|
| experiment_manifest.json | 계획·데이터 해시, 코드 파일별 SHA-256과 합성 해시, Git HEAD/작업 상태, Python/플랫폼, 조건별 요약, 대응 비교, 생략 조건 |
| readiness.json | 환자별 부족한 라벨과 정답 workflow, 각 실험의 실행 가능 범위 |
| n…json | 실제 생성된 도착을 포함한 source_cases, 최종 상태·이벤트, 5장/6장 지표, 적용된 설정, 실행 상태 해시 |
| summary.md | 조건별 완료율·대기·진단시간, 계산 가능한 실행 수, 데이터 부족 및 범위 제한 |

코드 해시는 app의 Python/JSON, requirements.txt, AGENTS.md를 대상으로 한다. 비밀 환경변수나 .env 값은 수집하지 않는다. 환경 전체를 동결한 것은 아니므로 라이브러리 및 OS 수준까지의 완전한 재현성 증명은 아니다.

전체 tick 스냅샷은 반복 실험에서 생략하여 메모리를 줄이고 최종 상태·이벤트는 유지한다. 기존 preview는 기본적으로 스냅샷을 계속 저장한다. 보고서의 입력과 flow_config로 같은 실행을 재구성할 수 있다.

통계는 실행별 지표의 기술통계다. missing/censored 실행은 분모와 제외 정보를 남기며 0으로 대체하지 않는다. 조건 요약의 평균은 평가 가능한 실행의 평균이지 모든 환자를 합친 micro 값이 아니다. 반복 seed가 독립적인 임상 표본을 만들어 주는 것은 아니다. 같은 코호트가 반복되는지 distinct_realized_cohorts도 기록한다. 종합점수·p-value·통계적 유의성 주장은 생성하지 않는다.

## 아직 실행할 수 없는 연구 비교

1. **Static QA vs Sequential:** 같은 case_id의 정적 QA 예측과 정답을 보지 않는 순차 정책의 결과가 필요하다. 현재 데모를 그 결과로 대신 사용하지 않는다.
2. **Base vs LoRA:** 모델·어댑터 버전, 프롬프트, 추론 설정과 독립 평가 결과가 필요하다. 이 실행기는 해당 모델을 호출하지 않는다.
3. **동일 시나리오 다중 LLM 과정 비교:** 공통 지표는 있으나 독립적인 모델 실행 결과와 전문가 workflow가 필요하다.
4. **임상적 안전성:** 현재 시나리오의 필수/고려 검사·허용 협진·중요 행동·중증/악화 위험 라벨 및 악화 임계값이 부족하다. readiness와 각 지표 status로 드러낸다.

## 검증

전체 테스트 48개에 기존 72개 설정 조합 검사가 포함된다. 추가 테스트는 계획 재현성·입력 불변성·자원 조건의 대응 비교·부족한 환자 수 생략·조건 혼입 차단·8명 논리 침상과 전문과 배정·스냅샷 복원·미완료/누락값·물리 뷰어 차단을 검증한다.

실제 5명 시나리오로 36개 실행이 완료되었다. 지표 출처 메타데이터까지 포함한 최종 실행 결과는 `outputs/reports/chapter7_experiments_verified/summary.md`에서 확인할 수 있다. 이는 해당 demo와 계획에서의 결과이며 실제 병원의 수요 또는 LLM 성능 개선의 증거가 아니다.

# 병렬 엔진의 수학적 계약과 보장 범위

이 문서는 6장의 모델을 코드에 연결한 정의와 조건부 논증이다. 아래 등식의 유도, 실행 시 불변조건 검사, 유한 테스트를 구분한다. 전체 프로그램의 형식 검증이나 실제 병원에 대한 임상 검증을 완료했다는 뜻은 아니다.

## 1. 상태와 전이 — 6.1

상태를 `S=(t, C, Q, R, E, M)`으로 둔다. C는 환자 상태, Q는 대기열, R은 자원 소유권, E는 예약 이벤트, M은 측정 누적값이다. 설정과 도착 시각이 정해진 이후 한 tick은 결정적 함수 `S(t+1)=F(S(t))`다. 난수는 도착 시각 생성 시 로컬 seed를 사용한다.

종료 환자는 큐·이벤트·점유 자원을 보유하지 않는다. 미종료 환자는 도착 큐, 임상 큐, 향후 이벤트 중 하나 이상으로 도달 가능해야 한다. 큐 간 중복은 허용하지 않는다. 이벤트와 서비스 자원 소유권이 일치해야 한다. 이 조건을 tick 전후 검사한다. 임상 상태와 자원 상태는 같지 않으므로 침상 점유와 검사 진행은 동시에 가능하다.

## 2. 환자 및 대기열 보존 — 6.5 확장

각 큐 q에 대해 시각 T의 누적 진입 A_q, 누적 이탈 D_q, 현재 대기 Q_q는 다음을 만족한다.

`A_q(T) − D_q(T) − Q_q(T) = 0`

관측 시작을 a라 하고, 각 큐 방문 j의 관측된 진입을 b_j, 이탈을 e_j라 하면:

`Σ[t=a..T−1] Q_q(t) = Σ_j max(0, min(e_j,T) − max(b_j,a))`

아직 이탈하지 않은 방문은 e_j=T로 잘라서 포함한다. 동일 환자의 재방문은 별도 방문이다. 매 구간에서 Q_q는 대기 중인 방문의 지시함수 합이므로 합의 순서를 바꾸면 우변이 된다. 따라서 이는 유한 구간에서의 정확한 회계 항등식이다. 종료된 방문만 평균에 포함하면 일반적으로 성립하지 않는다.

엔진은 이 차이와 진입·이탈 수 차이를 매 tick 확인한다. 보존 오차는 반올림 허용 없이 0이어야 한다. 분 단위 정수 계산을 사용한다.

동일하게 병원 전체에 대해:

`N_cohort = N_not_arrived + N_in_system + N_completed`

`Σ[t=a..T−1] N_in_system(t) = Σ_i observed_stay_i(a,T)`

환자별 체류는 도착부터 완료까지이며 미완료 환자는 T에서 자른다. 구형 스냅샷은 복원 시각부터 새 적분 구간을 시작한다. 병원 전체 체류에는 큐 대기·이동·진료·검사·결과 보류가 포함된다.

## 3. 용량과 이용률 — 6.6, 6.7

자원 r의 각 단위 k에 대해 `x_ik(t)∈{0,1}`은 환자 i 소유 여부다.

`Σ_i x_ik(t) ≤ 1`, 따라서 `Σ_i Σ_k x_ik(t) ≤ c_r`.

각 자원 단위가 하나의 소유자 필드만 갖고, idle 상태에서만 획득하며, pool 크기가 c_r와 일치하는지 검사하므로 정상적으로 통과한 상태의 점유량은 용량을 초과할 수 없다. 이 논증은 소유권 모델에 대한 것이며, 업무량이 현실적으로 충분하다는 보장은 아니다.

`B_k=Σ_t 1[resource k occupied at t]`, `U_r=Σ_k B_k/(c_r T)`.

각 지시함수는 0 또는 1이므로 `0≤B_k≤T`, `0≤U_r≤1`이다. 실행 중 busy 시간의 경계를 검사한다. T=0 또는 용량 0에서는 나눗셈을 하지 않는다. 이동과 예약도 점유에 포함된다.

## 4. 외생 수요와 부하 — 6.2, 6.3

`λ_r`은 자원에 요청되는 방문/분, `m_r=E[S_r]`은 단일 방문의 평균 점유 분, `μ_r=1/m_r`다.

`ρ_r=λ_r m_r/c_r=λ_r/(c_r μ_r)`.

수요가 양수일 때 `ρ_r<1`을 만족하는 최소 정수 용량은 `floor(λ_r m_r)+1`이다. 용량 0은 부하 숫자를 null로 반환하고 `no_capacity`로 표시한다. 수요 0의 필요 용량은 0이다. `ρ≥1`은 부하 조건 불충족을 표시하지만 유한 코호트가 반드시 미완료된다는 뜻은 아니다.

이는 입력 평균에 따른 부하 조건이며, 자원 간 blocking과 공유·라우팅이 있는 네트워크의 충분 안정 조건이 아니다. 실측 처리량은 용량에 의해 제한되므로 이를 λ로 대체하지 않는다. 수요 입력이 없으면 `missing_exogenous_demand_data`로 반환한다.

설정의 선택적 `demand` 예시(수치는 설명용 가상 값):

```json
{
  "demand": {
    "er_doctors": {
      "arrival_rate_per_minute": 0.2,
      "mean_service_min": 2,
      "model": "mm1_fixed_priority",
      "priority_arrival_rates": [0.1, 0.1]
    }
  }
}
```

대상 그룹은 capacities의 triage_nurses, er_doctors, er_beds, lab_slots, imaging_slots다. 단순 부하만 필요하면 model과 priority_arrival_rates를 생략한다. 원시 평균 서비스시간은 분석에서 올림하지 않는다. 실제 엔진의 정수 시간 설정과 구분한다.

## 5. 우선순위 대기행렬 참고식 — 6.4

높은 우선순위부터 k=1,…,K, 공통 서비스율 μ에 대해 `ρ_k=λ_k/μ`, `ρ=Σρ_k`로 둔다.

`E[Wq_k]=(ρ/μ)/[(1−Σ[j<k]ρ_j)(1−Σ[j≤k]ρ_j)]`.

조건: 서버 1, 독립 Poisson 도착, 공통 지수 서비스시간, 고정 비선점 우선순위, 정상상태, 총 부하 ρ<1. 클래스 도착률 합이 총 도착률과 일치하는지 검사한다. 설정에서 참고 모델을 명시해도 c≠1 또는 ρ≥1이면 계산하지 않는다.

본 엔진의 가중치 재정렬·정수 tick·유한 코호트·여러 자원은 이 가정을 충족하지 않는다. 따라서 출력은 항상 `hypothetical_reference_only`이며 엔진 예측 대기시간이라는 이름을 사용하지 않는다.

## 6. 동적 우선순위와 악화 — 6.8, 6.9

`P_i(t)=α(6−ESI_i)+β W_i(t)+γ D_i(t)`, 가중치는 유한한 비음수이고 전부 0일 수 없다. W는 실제 큐 대기 누적량이다. 임상적 위급 환자 보호를 위해 ESI 1 또는 Critical을 먼저 비교한 뒤 P와 도착 순서를 비교한다. 이미 시작한 업무는 선점하지 않는다.

β>0이면 대기 중 같은 환자의 시간항은 증가한다. 그러나 이것만으로 무한 도착 하에서 기아 방지나 최적성을 증명할 수 없다. 높은 보호 등급 환자가 계속 유입되면 낮은 등급의 유한 대기를 보장할 수 없기 때문이다.

악화 상태는 명시된 기준 시계 u에 대해 Stable(u<τ1), Worsening(τ1≤u<τ2), Critical(u≥τ2)이다. `0<τ1<τ2`를 검사한다. 시계는 도착 후 시간 또는 누적 큐 대기다. 임계값이 없으면 임의 전이를 만들지 않는다. 이는 6장의 threshold 모델이며, 확률적 질병 진행이나 처치 후 회복 모델은 아니다.

## 7. WTE — 6.10

`W_i=first_evaluation_i−arrival_i`, `MWT=mean(W_i)`, `CPWT=mean(W_i | independent critical label)`.

`WTE=1−CPWT/MWT`.

필수 조건: 모든 환자에게 독립 boolean 라벨, 전원 최초 평가 완료, 중증 환자 1명 이상, MWT>0. 조건 미충족 시 null. WTE는 음수가 될 수 있으므로 0~1로 강제 보정하지 않는다. 이 값만으로 진단 품질이나 인과적 정책 효과가 증명되지는 않는다.

## 8. 진행 정체와 검증 수준

`progress.currently_stalled`는 미완료 환자가 있는데 미래 도착·예약 이벤트·사용 가능한 자원·반환 가능한 시간 자원이 모두 없을 때 true다. 큐별 필요한 자원과 `no_configured_resource`, `resource_occupied`, `eligible_next_dispatch`를 보고한다. 이는 현재 고정 자원 모델에서의 정체 진단이며 임의의 미래 정책에 대한 교착 부재 증명은 아니다.

테스트 23개(그중 1개는 72개 설정 조합 탐색)가 통과했다. 5명 시나리오는 73분에 완료했고, 재원시간 적분과 환자별 체류시간 합은 각각 189 patient-minutes로 같았다. 전체 및 각 큐의 수·시간 잔차는 모두 0이었다. 산출물: `outputs/reports/chapter6_math_audit/hospital_flow_metrics.json`.

# 새 UI 제안: Clinical Research Workbench

## 권장 기술

React + TypeScript 프런트엔드, Python FastAPI 백엔드를 권장한다. 화면은 새로 구현하고 기존 시뮬레이터·연구 실행기·평가 모듈을 API 뒤에서 재사용한다. React는 컴포넌트별 상호작용과 상태 표현을 지원하고, FastAPI는 API 명세와 대화형 문서 생성을 지원한다.

근거: [React 공식 문서](https://react.dev/learn/your-first-component), [FastAPI 공식 문서](https://fastapi.tiangolo.com/tutorial/first-steps/).

대안은 Streamlit이다. Python 기반 다중 페이지 데이터 앱을 빠르게 만들 수 있어 일회성 결과 대시보드에 적합하다. 이번 프로젝트는 장기 실행 제어·환자 방문 탐색·조건별 비교가 핵심이므로 최종 UI로는 React/FastAPI를 추천한다. 이는 프로젝트 요구에 따른 설계 판단이다. [Streamlit 공식 문서](https://docs.streamlit.io/get-started/fundamentals/summary)

## 화면 구성

| 화면 | 주요 내용 |
|---|---|
| 실험 설정 | 데이터 선택, B0~B4/R0, 반복 수, top-k, 모델 버전, 실행 전 검사 |
| 실행 현황 | 조건×반복 상태, 진행 방문, 호출·토큰·실패 수, 취소·재개 상태 |
| 환자 기록 | 방문 타임라인, 당시 공개된 정보, 기억 출처·갱신·충돌 후보 |
| 의사결정 상세 | 관측 → 검색 기억 → 전문과 점수 → 행동별 VoI → 선택 이유 |
| 결과 비교 | 정확도/완료율/비용/행동 수, coverage, paired 차이·CI, 실패 사례 |
| 내보내기 | CSV·JSON·논문 표, 고정된 실험 설정과 실행 ID |

실행 중 화면은 왼쪽 환자·방문 목록, 중앙 시간순 의사결정, 오른쪽 기억/라우팅/VoI 상세 패널로 구성한다. 관측되지 않은 gold label·미공개 검사 결과는 실행 정보와 분리하고 평가 모드에서만 노출한다. NA와 0을 시각적으로 구분하고, 합성/미검수/실제 모델 호출/저장 응답 재평가를 명확히 표시한다.

## 구현 순서

1. 저장된 `manifest.json`, `results.json`, 방문 보고서를 읽는 결과 탐색기. 모델 호출 없이 개발 가능.
2. 실험 설정·입력 검증과 별도 worker 실행. 요청 처리 스레드에서 LLM 실행을 오래 붙잡지 않는다.
3. 상태 API와 진행 스트림, 취소. 실행 상태·출력을 디스크에 보존한다.
4. 방문 타임라인과 기억·라우팅·VoI 상세 표시.
5. 조건별 비교와 논문 내보내기.

배치 실행기의 재개·취소 기능은 현재 완성되어 있지 않으므로 UI 버튼보다 worker 상태 관리부터 구현한다. 초기에는 단일 로컬 worker와 파일 기반 결과 저장으로 시작하고, 동시 사용자 요구가 생기면 큐/DB를 추가한다. 기존 UI 삭제·새 프런트엔드 생성은 이번 제안 범위에 포함하지 않았다.
